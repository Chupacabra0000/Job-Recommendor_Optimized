# AI Job Recommender

Интеллектуальная система поиска и рекомендации вакансий, которая анализирует резюме пользователя и автоматически подбирает наиболее релевантные вакансии с использованием **NLP, TF-IDF, Sentence Transformers и FAISS**.

Приложение получает актуальные вакансии через **API hh.ru**, извлекает из резюме ключевые термины, выполняет семантическое сравнение резюме с описаниями вакансий и формирует список наиболее подходящих предложений.

## Основные возможности

* 📄 Загрузка резюме в формате PDF
* 🔎 Автоматическое извлечение ключевых терминов из резюме
* 🧠 Семантическое сопоставление резюме и вакансий
* 🌐 Получение актуальных вакансий через API hh.ru
* 📊 Ранжирование вакансий по степени семантического сходства
* ⚡ Использование FAISS для быстрого векторного поиска
* 💾 Кэширование вакансий и векторных представлений
* 📍 Выбор региона и города
* ⭐ Добавление вакансий в избранное
* 👤 Регистрация и авторизация пользователей
* 📑 Работа с несколькими резюме
* 🔄 Сохранение результатов предыдущих поисков
* 🗃️ Локальное хранение данных в SQLite
* 🧪 Набор автоматических тестов для основных компонентов

### 1. Анализ резюме

Пользователь загружает PDF-файл.

Система использует **PyMuPDF (`fitz`)** для извлечения текста из документа.

После этого из текста выделяются наиболее значимые термины с использованием TF-IDF и собственного токенизатора, поддерживающего русский и английский языки.

Например:

```text
Python
SQL
Java
Linux
Docker
Git
```

### 2. Поиск вакансий

Выделенные термины используются для формирования запросов к API **hh.ru**.

Приложение умеет:

* выбирать регион;
* ограничивать период публикации;
* выполнять несколько поисковых запросов;
* получать страницы результатов через API;
* объединять результаты;
* удалять дубликаты вакансий.

Клиент API реализован в `hh_client.py`.

Для временных ошибок API предусмотрены повторные запросы с exponential backoff и обработкой HTTP-кодов `429`, `500`, `502`, `503` и `504`.

### 3. Формирование текста вакансии

Для каждой вакансии формируется единый текстовый документ, включающий такие данные, как:

* название позиции;
* работодатель;
* формат работы;
* требования;
* обязанности;
* информация о зарплате;
* описание вакансии.

Этот текст используется для последующего создания embedding.

### 4. Семантическое представление

Для преобразования текста в векторное представление используется модель:

```text
sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2
```

Это позволяет сравнивать тексты не только по точному совпадению ключевых слов, но и по их **семантическому сходству**.

Например, резюме:

```text
Python developer with SQL and REST API experience
```

может быть релевантно вакансии, в которой формулировки отличаются, но описывают схожие требования.

### 5. FAISS

Полученные embeddings нормализуются и используются для поиска по векторному пространству.

В проекте используется **FAISS**, в том числе `IndexFlatIP`, для вычисления similarity между векторами.

Это позволяет эффективно ранжировать вакансии по степени сходства с резюме.

# Основные компоненты

## `app.py`

Основное Streamlit-приложение.

Отвечает за:

* пользовательский интерфейс;
* загрузку PDF;
* авторизацию;
* выбор региона;
* работу с резюме;
* получение вакансий;
* запуск поиска и ранжирования;
* отображение результатов;
* избранные вакансии;
* сохранение результатов поиска;
* работу с глобальным индексом.

---

## `model.py`

Содержит класс:

```python
JobRecommendationSystem
```

Он реализует базовую логику сопоставления резюме и вакансий.

Основные возможности:

```python
score_all_jobs(resume_text)
```

Вычисляет similarity score между резюме и вакансиями.

```python
explain_match(resume_text, job_text)
```

Формирует объяснение совпадения на основе ключевых терминов.

В качестве основного алгоритма используется **Sentence Transformers**, а TF-IDF применяется для анализа и объяснения совпадений.

---

## `hh_client.py`

Клиент API hh.ru.

Основные функции:

```python
search_vacancies()
fetch_vacancies()
vacancy_details()
```

Поддерживается:

* пагинация;
* фильтрация по региону;
* ограничение периода;
* сортировка по времени публикации;
* повторные запросы при временных ошибках API;
* обработка `Retry-After`.

---

## `hh_areas.py`

Работает с иерархией регионов hh.ru.

Позволяет получить:

```text
Россия
 ├── Москва
 ├── Новосибирская область
 │    ├── Новосибирск
 │    └── ...
 ├── Санкт-Петербург
 └── ...
```

Данные о регионах кэшируются локально, чтобы уменьшить количество запросов к API.

---

## `tfidf_terms.py`

Отвечает за извлечение ключевых терминов из текста резюме.

Используется:

```python
TfidfVectorizer
```

Реализован собственный multilingual-friendly tokenizer с поддержкой:

* русского языка;
* английского языка;
* технических терминов;
* символов вроде `C++`, `C#`, `.NET`.

Из текста можно получить `top_k` наиболее значимых терминов.

---

## `vector_store.py`

Отвечает за постоянное хранение embeddings.

Вместо повторного вычисления уже существующих векторов приложение сохраняет их локально и использует повторно.

Векторное хранилище использует:

* `NumPy`;
* memory-mapped файл;
* массив идентификаторов;
* метаданные модели и размерности.

Для используемой multilingual-модели размер embedding составляет:

```text
384
```

---

## `global_faiss_index.py`

Отвечает за хранение и загрузку глобального FAISS-индекса вакансий.

Индекс позволяет повторно использовать заранее рассчитанные embeddings вместо полного пересчёта при каждом поиске.

---

## `global_index_manager.py`

Управляет глобальным индексом.

Проект использует стратегию:

```text
Incremental update
        +
Periodic full rebuild
```

Обычно в индекс добавляются новые вакансии, а полная перестройка выполняется периодически.

В текущей реализации полная перестройка предусмотрена примерно раз в **24 часа**.

---

## `db.py`

Отвечает за работу с SQLite.

Используется для хранения данных приложения, включая:

* пользователей;
* сессии;
* резюме;
* избранные вакансии;
* результаты сохранённых поисков;
* глобальные вакансии;
* состояние индекса.

# Кэширование

Проект активно использует несколько уровней кэширования.

### Streamlit cache

Используется для кэширования:

* результатов API-запросов;
* информации о регионах;
* деталей вакансий;
* загруженной модели.

### SQLite

Используется для сохранения вакансий и пользовательских данных.

### Vector Store

Embeddings сохраняются на диске и повторно используются.

### FAISS

Индекс вакансий сохраняется и обновляется инкрементально.

Таким образом, приложение старается не выполнять дорогостоящие операции повторно.
